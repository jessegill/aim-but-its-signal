1 · Window chrome

The app is macOS-only and every window is frameless, so the title bar is the real chrome: it carries -webkit-app-region: drag and the only minimize / maximize / close controls, on the right, Windows-style. Buttons re-declare no-drag so they never become dead zones inside the drag region.

3 · Buddy list window

Narrow and tall. Rows are 16px with almost no padding — the density is doing as much work as the colours. There is no presence anywhere in this window: no status icons, no colour-by-availability, no idle time, no away text, and nothing is sorted or grouped by who happens to be reachable. Every buddy glyph is identical by design.

The two numbers in Buddies (3/8) are unread / total, not online / total. AIM's original meaning was presence and is unavailable, so the slot was given the most useful message-derived number instead: how many buddies in that group have unread messages. Hover any group header — the tooltip says so in words, so nobody has to guess.

4 · IM window

History pane on top, formatting toolbar in the middle, input pane below, Send bottom-right. No chat bubbles anywhere — plain flowed text, inline (10:47:03 PM) timestamps, bold coloured sender names, own text red and theirs blue, which were AIM's own defaults. Nothing is right-aligned; alignment-as-authorship is a much later idea.

The status bar carries the typing indicator. Typing is not presence — it is a real per-message protocol event, so it is built. What is not there: any claim about whether the other person is online, idle, or away.

5 · Security notices

SPEC.md §8: when retro authenticity conflicts with a security signal, security wins. These are styled for 2003 — bevelled panel, hard edges, hazard rule — but they are deliberately the loudest thing on screen, and there is no prop that hides them. “I understand” removes the buttons only; the notice stays in the conversation because the event stays in history.

The wording never reassures. A safety-number change has a benign cause and a hostile one, this client cannot tell them apart, and so it says exactly that.

6 · Sign-on window — all four connection states

The 2003 sign-on window had a screen name and a password. Neither exists here — this client links as a secondary device and never sees a credential — so the shape is kept and a QR code takes the password box's place. The banner mark is original artwork: no running man, no AOL wordmark, nothing extracted (SPEC.md §9, §10). The product name is host-supplied rather than hardcoded to anything trademarked.

All four states from SPEC.md §8 are shown. The indicator reports this device's link to the service — it is not a status dropdown, and there is nothing here to set yourself “away” with.
